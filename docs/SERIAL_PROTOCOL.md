# 单串口 Modbus RTU 联调

数字孪生作为虚拟设备从站，发送端作为主站。接收端仅打开一个串口，在这条总线上响应多个设备站号。主站发出设备命令，虚拟设备计算运动和工艺反馈，并通过 Modbus 应答返回。

## 两根 USB 转 TTL 的操作

本次配置：**数字孪生接收 COM10，控制程序发送 COM3，115200 / 8N1，无流控**。

1. 两根转换线的 TX、RX 交叉互接，GND 相连，VCC 不相连；两根线使用相容的 TTL 电平。
2. 双击项目目录的 `run_serial_test.bat`，自动打开两个程序及上述两个端口。也可以分别运行 `run_receiver.bat` 和 `run_sender.bat`，在界面选择端口后点击“打开串口”。
3. 发送端选择口味和包装，点击“发送单件工艺”。配方选择、各轴 PR、灌装、阀门、夹爪和出料命令会逐条发送；接收端显示动作、液面和设备状态。
4. 两侧日志应持续出现 TX / RX，接收端 CRC 错误计数为 0。可用手动运动、灌装、执行器按钮，以及底部的通用寄存器工具单独测试。
5. “中止 / 暂停”发送产线停止指令。关闭发送端串口后，接收端在 5 秒通信超时后冻结动作并标记数据无效。重新打开发送端可恢复通信；已中止的发送队列需要重新发起。

串口号和波特率可在界面修改并记住。配置默认值、校验位、停止位、超时和运动参数位于 [`config/serial/protocol.json`](../config/serial/protocol.json)。修改协议配置文件后重启程序。接收端连接设置与发送端分开保存。

自定义一键启动端口顺序：

```bat
run_serial_test.bat COM10 COM3
```

接收模式的阶段按钮及离线运行按钮不下发控制，设备动作来自接收到的命令。右上角可以切换离线演示；`run_demo.bat` 直接进入离线模拟。

## 寄存器和数据格式

以下地址均为报文中的 **0 基地址，使用十六进制**。例如 `0x6002` 对应请求中的 `60 02`。支持 FC03、FC04、FC05、FC06、FC16（十进制 16，即报文 `0x10`）。RTU 帧附 CRC16，低字节先发。

| 设备 | 功能码 / 地址 | 含义 |
|---|---|---|
| 七个运动电机 | FC06 `0x6002` | PR 触发，写入 `0x10 + PR`，PR 范围 0–15；轴 PR 必须有标定 |
| 运动电机 | FC03 `0x602C` × 2 | 虚拟位置，int32 大端；`0x0020` × 2 是同一位置的兼容读口 |
| 运动电机 | FC04 `0x0000` | 0=动作中，1=完成 |
| 运动电机 | FC03 `0x2203` / `0x1003` | 虚拟驱动诊断，正常为 0 |
| 三个灌装头 | FC06 `0x0010` / `0x0011` | 容量 mL / 灌装时长 ms，u16 正整数；支持 FC16 原子设置二者 |
| 三个灌装头 | FC05 线圈 `0x0000` | `0xFF00`=开始灌装，`0x0000`=停止；重新开启开始新一次灌装 |
| 三个灌装头 | FC04 `0x0000` | 0=尚未灌满，1=完成 |
| 三个灌装头 | FC03 `0x0012` | 已灌装量，u16 mL |
| Gripper / CapFeeder | FC05 线圈 `0x0000` | 夹爪 / 供盖开关 |
| RinseValve / CIPValve | FC05 线圈 `0x0012` / `0x0013` | 冲洗 / CIP 开关 |
| Relay | FC05 线圈 `0x0008`–`0x000E`、`0x0014` | 沿用原配置输出点，其中 `0x000B` 封口、`0x000C` 喷码、`0x000D` 贴标 |
| ContainerSensor | FC04 `0x0000` | 上瓶到位 / 已夹持 |
| BottleSensor | FC04 原工位地址 | `0x0034`–`0x0037`、`0x0039`–`0x003B`、`0x0040`–`0x0047`；`0x0046` 为盖到位 |
| LevelSensor | FC04 `0x0038`–`0x003B` | 虚拟液位到位，1=达到目标的 98% |
| PressureSensor | FC03 `0x0010` × 2 / `0x0012` × 2 | 原接口 float32 小端，整个四字节按 little endian 排列 |
| FlowMeter | FC06 `0x0001` | 清零累计体积，写入值沿用原配置的 0 |
| FlowMeter | FC03 `0x0000` × 2 | 原接口 float32 小端，mL |
| Torque | FC03 `0x0030` × 2 | 原接口 float32 小端，N·m |

所有设备还支持 FC04 `0x0000` 诊断轮询。容器传感器保留原语义；其余端点以完成 / 就绪信号响应。发送端每次只等待一个请求的应答；空闲及工艺等待期间轮询设备，避免将正常等待误判为通信失效。

位置读回使用 `counts_per_scene_unit` 标定（默认每场景单位 1000），界面显示的是展示单位。压力、扭矩、液位、体积等反馈由模型根据接收指令计算，不代表真实仪表采集值。三种规格仍共用三个原灌装头。

## 新增的产线管理接口：站 240

此接口补充原配置没有通过串口传输的配方和 UI 阶段信息。保持原设备寄存器不变。使用 FC03 读、FC06 / FC16 写。

| 寄存器 | 含义 |
|---|---|
| `0x0100` | 配置：0=原版六配方，1=扩展九配方 |
| `0x0101` | 口味：0=橙汁，1=苹果汁，2=葡萄汁 |
| `0x0102` | 包装：0=2 L，1=330 mL，2=250 mL；包装 2 仅扩展版有效 |
| `0x0103` | 工艺阶段，0–11，对应界面十二阶段；只更新阶段显示，不代替设备动作指令 |
| `0x0104` | 0=停止 / 冻结，1=运行 / 恢复，2=暂停，3=重置虚拟设备 |
| `0x0105` | 主站成品计数，u16 |

推荐用 FC16 从 `0x0100` 开始一次写入三项选择，避免切换配置途中出现无效组合。原版写入第三规格会返回异常并保留当前状态。

没有使用站 240 时，也可以直接用原设备命令驱动。接收端依据上瓶 PR、灌装头 ID 和容量识别已有配方，提供基本阶段推断；完整的十二阶段遥测由站 240 提供。出料成功时也可由虚拟设备增加成品计数。

## 将同一套站号交给原配置解析引擎

原始两份案例快照及其哈希保持不变。导出工具复制所选案例的 L1/L2/L3/L4 和变量，只替换设备注册表的总线与站号，生成独立的单串口案例：

```powershell
python tools/export_single_bus_case.py --port COM3 --profile extended --output build/single_bus_case
```

让原引擎加载导出目录下的 `device_registry.json`、`system_variables.json` 和相应 L4 入口即可。原引擎占用 COM3，数字孪生占用 COM10。重建已有导出目录需要 `--overwrite`。使用原引擎时关闭内置发送端，保证同一端口只有一个主站程序。

## 报文质量与测试

CRC 错误和不完整帧不执行、不应答，也不刷新通信时限。未知单播站号静默忽略。已配置站的非法功能、地址和数值返回 Modbus 异常码 01、02、03。FC16 在全部参数有效后才写入。广播站号 0 只执行适用的写操作，不应答。

接收器处理分包和粘包；不完整缓存默认 50 ms 后丢弃，以容纳 USB 转串口的分批送达。主站在请求间保留间隔，校验站号、功能码、数量及写回显；超时 / 异常后终止当前工艺队列，不自动重发动作指令。

```powershell
python tools/verify_serial.py
python tools/verify_serial.py --hardware --receiver-port COM10 --sender-port COM3
python tools/verify_serial.py --hardware --gui
```

最后一条会打开两个独立 GUI 进程，通过真实 COM3 / COM10 完成葡萄汁 250 mL 单件工艺，保存接收端和发送端截图，并验证发送端退出后的接收超时。运行测试前关闭占用这两个端口的其他程序。结果保存在 `verification-serial.json`。

协议参考：[Modbus Organization 规范入口](https://www.modbus.org/modbus-specifications)。
