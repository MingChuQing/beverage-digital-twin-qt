# 验证器来源与演示边界

原仓库：[MingChuQing/industrial_config_engine](https://github.com/MingChuQing/industrial_config_engine)，版本 `00f0f1ff292a58c8793aa7ab3b2d327c44bf47a9`。

`engine/` 保存原 C++ 引擎、头文件和 `tests/defect_probe.cpp`；`vendor/` 保存原增量检查器和两个独立解释器。原文件保留，新的 API 编排位于 `pipeline.py`。具体来源与冻结输入哈希见 `provenance.json`。原项目使用 GPL-3.0-or-later，本项目随附 GPLv3；nlohmann/json 保留原 MIT 许可。

`inputs/context.json`、`inputs/prompt.txt` 是原案例的输入：三种口味新增 250mL；坐标和流量来自预置工程数据。该输入**只包含原六配方**，不含新增配方答案。`references/` 保存评估侧独立单体参考，只用于验证，**不发送给 DeepSeek**。测试夹具 `tests/fixtures/extension_changes.json` 是原仓库历史记录，用于明确标注的 mock 回归，不冒充本次 API 输出。

第一关：修改白名单、类型、容量/时长/点位/查找表约束、冻结 L1/L2；调用原 C++ 解析器、结构检查 API 和虚拟执行器执行九个入口。原引擎使用窄路径，其工作副本放在英文临时目录中，证据保存在本轮目录。

第二关：原 Python 双解释器比较每个配方的完整带时间戳协议轨迹；完整十二阶段、两批六瓶、实际虚拟工艺时长；九个正常配方和十一个预置故障；旧六配方与重新运行的基线一致。故障只作用于原配方索引 0，不表示新增配方逐一覆盖全部故障。

第三关：操作者核对自然语言需求、配置差异和工程点位后点击审核。自动化测试记录为 `TEST_ONLY`，不能作为人工语义审核证明，普通回放不接受测试审核记录。

应用：候选配置和轨迹均绑定 SHA-256，应用/回放前复核；修改后必须重新验证。候选不覆盖原始案例文件；不允许 AI 改 L1/L2、设备地址或输出任意命令。

串口：从经过独立解释和比较的候选 JSON 轨迹提取实际写指令，沿用同一站号表，由 Qt 逐条发送、校验 CRC 与应答。**这是已验证写轨迹回放，尚不是原引擎的在线条件解释执行**；现场读反馈只用于设备展示和通信状态。运动与灌装保留接收端时长，其他工艺等待加速 50 倍。首瓶片段提取初始化、首瓶各阶段、CIP 和回零，不声称实际生产了十二瓶。完整模式保留十二瓶写序列。全量虚拟验证不加速、不删工序。

工艺、卫生及精度仍为合成设备模型，不能把 USB/TTL 与 3D 展示结果表述成真实工业设备验证。每次实际调用保留原始输出与实际服务模型名，不把历史论文模型名当作当前 API 返回模型名。
